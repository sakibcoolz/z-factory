# TASK-1001 — Global LLM Index & Complete Agent Guide

Status: **DONE**
Linear: [ZFA-56](https://linear.app/recruit-verse/issue/ZFA-56)

Phase: **10 — Agent-Ready Engineering & Full Catalog Go Simulation**

## Objective
Add an authoritative LLM Index to the Z-Factory home/engineering entry page so a browser-based coding/AI agent can understand the entire product before navigating it.

## Scope
- Explain Z-Factory purpose and engineering model.
- List active engineering areas and their routes.
- Explain which pages expose LLM Context.
- Document the recommended agent workflow.
- Document non-bypass rules and user-confirmation expectations.
- Keep the index derived from active navigation/features so it cannot silently drift.

## Acceptance criteria
- A browser agent can identify where to go for PLC, device, wiring, simulation, runtime and export tasks.
- The guide explicitly says to use normal Z-Factory UI and validation.
- It forbids direct database manipulation, hidden runtime writes and direct physical-output forcing.
- The index is visible from the application landing/home area.

## Decisions (owner, 2026-10-09)
- The index is its own page, `/llm-index`, with an LLM entry in the activity bar and a link on the Factories landing page (list and first-run welcome).
- It is also served as Markdown at `/llm-index.md`, from the same registry, for agents that fetch rather than render.
- ADR-0024 records the phase boundary this task implements: no embedded model, no MCP; the agent uses the normal UI and validation.

## Implementation
- `lib/navigation/activities.ts`: the activity bar as one registry (moved out of `components/shell/app-shell.tsx`, which now reads it), with the new `llm` entry.
- `lib/agent/llm-index.ts`: the registry. The product and its engineering model; what is real and what is simulated; 17 engineering areas, each naming the route builders it covers (as `[factoryId]`-style patterns), its activity, purpose, the tasks to bring there, the decisions to ask the user for, and whether it has an LLM Context tab (none yet); the files an agent can fetch; the nine-step workflow; seven rules with their sources.
- `lib/agent/llm-index-markdown.ts`: the index as Markdown; `app/llm-index.md/route.ts` serves it (`text/markdown`, `no-store`).
- `app/llm-index/page.tsx`: the page, one `section[data-llm-section]` per part and one `article[data-llm-area]` per area, with a contents sidebar and a Markdown button. It reads no database and needs no owner.
- `lib/navigation/routes.ts`: `llmIndex`, `llmIndexMarkdown`.
- Landing: an "LLM Index" button beside "+ New factory", and a welcome start action.
- Docs: ADR-0024, `docs/architecture.md` (agent-facing surface), `docs/design.md` (route map, activity bar, as built), `docs/api-contract.md`, `docs/status.md`.

## Evidence (2026-10-09)
- **Drift guard** (`lib/agent/llm-index.test.ts`): every builder in `routes` is listed exactly once, as a screen or a file (`newDevice` twice on purpose, compact and modular); every activity-bar entry has an area; patterns are real paths with placeholders; the workflow's areas exist; the Markdown has every section, area and route, and states each rule: normal UI and validation, no database manipulation, no hidden runtime writes, never force a physical output (ADR-0015), ask before decisions, no invented vendor facts, no embedded model or MCP.
- **Page and route** (`app/llm-index/llm-index.test.tsx`): the LLM activity is current and links to `/llm-index`; the Markdown button links to `/llm-index.md`; one named section per part and one article per area with its routes; a placeholder-free route is a link; every rule is a heading; `GET /llm-index.md` returns the renderer's output as `text/markdown`, uncached.
- **Landing** (`app/factories/factories.test.tsx`): the welcome links to the index.
- **Browser** (the owner's `next dev` on :3000, headless Chromium): `/llm-index` rendered with the contents sidebar, the sections and the area articles, the LLM entry current in the activity bar; `/factories` shows the LLM Index button; `/llm-index.md` answered 200 with `Content-Type: text/markdown; charset=utf-8`, 480 lines, 24 headings.
