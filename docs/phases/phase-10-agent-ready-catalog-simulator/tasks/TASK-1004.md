# TASK-1004 — Agent Navigation Index & Cross-Page Guidance

Status: **DONE**
Linear: [ZFA-59](https://linear.app/recruit-verse/issue/ZFA-59)

Phase: **10 — Agent-Ready Engineering & Full Catalog Go Simulation**

## Objective
Teach browser agents how user intentions map to Z-Factory pages.

## Examples
- Add a pump -> Devices / Catalog
- Select/configure PLC -> PLC
- Connect sensor -> Wiring
- Find available AI/DI/DO/AO -> PLC I/O
- Test high temperature -> Simulation
- Generate Thin Client config -> Engineering Export
- Understand whole plant -> Factory

## Acceptance criteria
- Navigation guidance is generated from active routes/features.
- Page-level contexts link back to relevant upstream/downstream engineering areas.

## Implementation
- `lib/agent/navigation.ts`: `AREA_GUIDANCE`, keyed by the areas of the LLM Index. Per area: the intentions a user may have, in their words ("add a pump, valve, sensor, drive or motor to the plant", "find available AI, DI, DO or AO channels", "generate the Thin Client Agent configuration", "understand the whole plant"); the areas usually visited before and after it; and `open(ids)`, its entry route for the ids at hand. `intentIndex()` lists every intention with its area; `routeIds(route)` reads the factory, PLC, device and module ids a page's route carries; `crossPageLinks(area, ids)` gives the areas before and after one area, linked where the ids allow.
- The LLM Index merges the guidance into its areas (`intents`, `upstream`, `downstream`) and renders a **Where to go** section: the intention table ("I want to… · Go to · Route", 55 rows) and how the areas follow each other; each area card also says what comes before and after it. The Markdown has the same section.
- `createLlmContext` ends every document's navigation with the generated upstream and downstream areas of the page's area, from the ids in the page's own route: items carry `relation`, the panel marks them "before" or "after" (`data-llm-relation`), and the Markdown prefixes them. An area the page cannot link for lack of an id is named without a link; an area the page already links is not repeated. No builder changed.
- Docs: `docs/design.md`, `docs/api-contract.md`, `docs/status.md`.

## Evidence (2026-10-10)
- **Guidance** (`lib/agent/navigation.test.ts`): every area of the index has guidance, with at least one intention, and names only areas that exist, never itself; the index carries the same guidance; the task's seven example intentions, and "understand the whole plant", each land on the right area (designer, catalog, plc, simulation, export, factory); `open` builds an area's route only with the ids it needs; `routeIds` reads routes with and without ids and ignores `new` and query strings; `crossPageLinks` from the PLC area gives designer and devices before, program, communication, runtime and export after, with routes; from the factory area without a PLC id, export is named without a link.
- **Framework** (same file, plus the adjusted model and panel tests): a program-page document gains "Before: PLC hardware and I/O", "After: Simulator and scenarios" and "After: PLC engineering export" with routes, carrying the area's purpose, and does not repeat the runtime link the page already had; the Factories list names "Factory overview and settings" without a link, since it has no factory id; a page outside the index gets nothing. The panel renders "before" and "after" marks and the links.
- **Index** (`lib/agent/navigation.test.ts`, `llm-index.test.ts`): the Markdown has "Where to go" with the intention rows, the first routes and the flow lines.

On the running Pump Station Demo's PLC program screen the panel's navigation ends with the generated "after: Runtime" link; the other cross-page areas were already linked by the PLC navigation, so they were not repeated.

## Acceptance
- Navigation guidance is generated from active routes and features: the guidance is keyed by the index's areas, which are keyed by the route builders; the entry routes come from `routes`; a missing or dangling entry fails the tests.
- Page-level contexts link back to upstream and downstream areas: every document's navigation ends with them, generated from the page's own route.
