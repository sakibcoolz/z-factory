# TASK-1006 — User-Decision & Recommendation Guidance

Status: **DONE**
Linear: [ZFA-61](https://linear.app/recruit-verse/issue/ZFA-61)

Phase: **10 — Agent-Ready Engineering & Full Catalog Go Simulation**

## Objective
Make missing engineering decisions explicit so an external browser agent knows when to ask the user instead of guessing.

## Scope
Expose ambiguities such as control method, device model choice, signal standard, I/O selection, protocol choice, process relationship or competing compatible endpoints.

## Acceptance criteria
- Missing decisions are visible in LLM Context.
- Safe defaults may be recommended but material engineering choices require user confirmation.
- Guidance never overrides Z-Factory compatibility/validation rules.

## Implementation
- `lib/agent/llm-context.ts`: `DECISION_KINDS`, the vocabulary of what an agent asks the user for (model, architecture, signal-standard, channel, protocol, relationship, endpoint, control-logic, run-state, write, test-input, parameters, scope, name, deletion), each with its meaning; `DecisionGuidance` (`kind`, `confirm` required or optional, `defaultChoice`, `enforced`); `LlmContextDecisionItem`; `DECISION_RULE`. A document's `decisions` are `LlmContextDecisionItem[]`, so the type refuses a decision without guidance: no builder can leave it out. The Markdown renders the guidance after the item; the panel marks it (`data-llm-decision`, `data-llm-confirm`) with the default and what is enforced.
- Every decision of every page carries its guidance: 21 existing ones, and new ones where the task's ambiguities arise: the signal standard when a free point accepts more than one (required; default the terminal's own standard; a mismatch is refused), the channel when a bank has more than one free (optional; default the first free compatible one, as the designer assigns; occupied and incompatible channels are refused), the protocol when a port offers more than one (optional; default Modbus TCP, the protocol the runtime serves), and the PLC to wire to when the factory has several (required). Defaults are named where one is safe (the suggested free subnet, the model's parameter defaults, READ access for every tag, the next free port, compact when only built-in I/O is needed); material choices are `required`.
- The LLM Index has a "Decisions to ask the user" section with the rule and the vocabulary, on the page and in the Markdown.
- Docs: `docs/design.md`, `docs/api-contract.md`, `docs/status.md`.

## Acceptance
- Missing decisions are visible in LLM Context: every page's decisions section, each item with its guidance.
- Safe defaults may be recommended but material choices require confirmation: `confirm: optional` items carry a `defaultChoice`; the rest are `required`; the rule says so on the index.
- Guidance never overrides validation: each decision names what is enforced, and the rule states that the application's rules decide what is possible.
