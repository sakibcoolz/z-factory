# TASK-1005 — Sidebar Cleanup & Active-Feature Navigation

Status: **DONE**
Linear: [ZFA-60](https://linear.app/recruit-verse/issue/ZFA-60)

Phase: **10 — Agent-Ready Engineering & Full Catalog Go Simulation**

## Objective
Remove navigation ambiguity for people and browser agents.

## Scope
Classify current sidebar entries as ACTIVE, PARTIAL, FUTURE, DUPLICATE or OBSOLETE. Keep ACTIVE production workflows in normal navigation. Hide future-only and non-working entries rather than presenting dead destinations.

## Acceptance criteria
- No normal sidebar item leads to an intentionally inactive workflow.
- Duplicate navigation is removed or consolidated.
- LLM Index reflects the same active navigation set.

## Implementation
- `components/shell/app-shell.tsx`: the settings gear is gone; the bar is exactly `ACTIVITIES`.
- `components/plc/stored-plc-shell.tsx`: `plcSections` (the PLC's screens) and `factorySections` (Simulator, Live Tags and Events narrowed to the PLC), rendered as two sections; no pending entries.
- `components/device/device-shell.tsx`: `deviceSections` lists only sections with a screen, drops Program and Versions when no adapter runs the model, and names the factory simulator "Simulator".
- `lib/docker/status.ts`: `DockerEngineStatus.openPlcImage`, the pinned image's tag, read from `RUNTIME_IMAGES` on the server; the explorer and the welcome show it. Components do not import server-only modules (lint rule).
