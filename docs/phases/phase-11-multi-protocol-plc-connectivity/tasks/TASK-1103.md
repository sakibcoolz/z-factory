# TASK-1103 — Thin Client Protocol Adapter Interface

Status: **PLANNED**

Phase: **11 — Multi-Protocol PLC Connectivity**

## Objective

Refactor the Thin Client PLC worker around a protocol-neutral adapter contract without weakening current Modbus behavior.

## Contract

Adapters expose lifecycle and data operations such as connect, close, health, read/subscribe, write command/setpoint and mapping validation.

Above the adapter, the worker uses one normalized tag/value model with timestamp, quality, logical tag id, data type and source PLC.

## Acceptance

- Current Modbus worker behavior passes existing tests through the adapter.
- MQTT/spool/replay code receives normalized telemetry only.
- Protocol-specific addresses/NodeIds do not leak into cloud business logic.
- Adapter failure is isolated to its PLC worker.
